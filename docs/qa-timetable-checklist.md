# 시간표 도메인 QA 체크리스트

실제 코드를 기준으로 재작성한 QA 시트입니다. 원본 시트에서 사실과 달랐던 전제는 아래에 정리했고, 대응 기능이 없는 항목은 체크리스트에서 빼고 맨 끝 "테스트 대상 제외"로 옮겼습니다.

### 표기

| 표기 | 뜻 |
| --- | --- |
| (표기 없음) | 원본 시트에 있던 항목. 화면 문구·경로만 구체화했고 검증 내용은 같다 |
| **〔신규〕** | 원본에 없던 항목. 코드를 읽고 새로 뽑았다 |
| **〔수정〕** | 원본에 있었으나 실제 구현과 달라 **검증 기준 자체가 바뀐** 항목 |
| **⚠️** | 현재 코드 기준으로 **실패가 예상되는** 항목. 그래도 테스트해서 실제 동작을 기록할 것 |

원본 항목 수 120개 → 이번 시트 232개. 원본 항목 중 8개는 대응 기능이 없어 "테스트 대상 제외"로 옮겼습니다.

## 시작 전에

### 원본 시트에서 정정된 전제

이 다섯 가지가 〔수정〕 표시의 대부분을 만든 원인입니다. 시트를 그대로 들고 테스트하면 **존재하지 않는 기능을 찾다 시간을 버리게 되는** 항목이므로 먼저 읽어주세요.

| 원본 기술 | 실제 동작 |
| --- | --- |
| 성적표 **이미지**에서 과목명·학점·등급 인식 | 이미지 인식이 아니라 **텍스트 붙여넣기**. 스마트캠퍼스 성적표를 드래그 복사해 붙여넣는 방식 |
| 성적은 서버 저장 없이 로컬에만 남음 | 로그인 상태면 **서버에 저장**됨. 비로그인일 때만 브라우저 로컬 저장 |
| 8. 채팅방 공강 — "구현 완료 후 QA" | **이미 구현 완료**. 채팅방 메뉴 "공강 맞추기"로 진입하며, 친구 비교 화면을 그대로 재사용 |
| 10. 강의 **1시간 전** 알림 | 5~180분 사이에서 사용자가 고르는 방식, **기본값은 10분 전** |
| 알림함 배지는 임시 구현 | 서버 기준으로 동작. 홈 화면의 "새 공지" 점은 별개 기능이니 같은 이슈로 묶지 말 것 |

### 테스트 환경 〔신규 섹션〕

- [ ]  웹은 **반드시 5173 포트**로 띄운다. 5173이 이미 점유되어 5174로 뜨면 서버가 모든 요청을 403으로 막아, 로그인 문제로 오인하게 된다.
- [ ]  로그인 만료로 보이는 현상이 나오면, 같은 계정으로 다른 화면이 정상 동작하는지 먼저 확인한다. dev 서버는 없는 경로나 서버 내부 오류도 "인증이 실패하였습니다"로 내려주기 때문에 실제 토큰 문제와 구분이 필요하다.
- [ ]  계정은 최소 3종 준비: 일반 계정, 관리자 계정, 시간표가 하나도 없는 신규 계정.
- [ ]  친구·채팅 항목 테스트에는 서로 친구인 계정 2개와, **친구가 아닌 채로 같은 단체 채팅방에 있는 계정**이 추가로 필요하다.
- [ ]  만료 안내 문구는 로그아웃 1회당 한 번만 뜬다. 반복 테스트하려면 재로그인해서 초기화한다.
- [ ]  Web · Android · iOS 세 환경에서 각각 진행한다. 홈 화면 위젯과 푸시 발송은 앱에서만 확인 가능하다.

## 1. 시간표 생성·관리

- [ ]  시간표 목록에서 학기 카드의 "＋" 버튼을 누르면 "시간표 추가" 모달이 열리고, 학기 선택과 이름 입력란이 보인다.
- [ ]  〔신규〕 이름 입력란에 "시간표 1", "시간표 2"처럼 중복 없는 이름이 자동으로 채워진다.
- [ ]  "저장"을 누르면 모달이 닫히고 방금 만든 시간표로 화면이 전환된다.
- [ ]  생성한 시간표가 시간표 목록과 메인 화면에 즉시 표시된다.
- [ ]  ⚠️ 이름을 비우고 저장을 시도하면 안내 문구가 표시된다. *(현재는 저장 버튼이 비활성화만 되고 문구가 없다. 이름 변경 모달도 동일)*
- [ ]  여러 시간표를 만들고 목록에서 원하는 시간표를 눌러 전환할 수 있다.
- [ ]  별 아이콘으로 대표 시간표를 바꾸면 메인 화면 진입 시 그 시간표가 열린다.
- [ ]  〔수정〕 대표 시간표를 바꾼 뒤, 친구가 내 시간표를 조회했을 때도 바뀐 시간표가 보인다. *(친구 화면은 별도 조회라 반영이 늦을 수 있으니 시간차를 두고 확인. 원본의 "위젯·알림 반영"은 웹에서 검증 불가라 10·11번으로 옮겼다)*
- [ ]  ⚠️ 대표 시간표를 삭제하면 남은 시간표 중 하나가 자동으로 대표가 된다. 삭제 후 별 아이콘이 어디에도 켜져 있지 않은 상태가 되지 않는지 확인한다.
- [ ]  마지막 시간표를 삭제하면 "등록된 시간표가 없어요" 안내와 함께 "시간표 생성하기", "이미지로 시간표 가져오기" 버튼이 표시된다.
- [ ]  앱 재실행과 재로그인 후에도 시간표 목록과 대표 설정이 유지된다.
- [ ]  〔신규〕 다음 학기가 미리 등록되어 있을 때 "＋" 버튼이 진행 중인 학기를 정확히 선택한다. *(과거 회귀 이력이 있는 지점)*
- [ ]  〔신규〕 이름을 변경한 뒤 다시 생성 모달을 열었을 때 자동 이름 번호가 꼬이지 않는다.

## 2. 강의 검색·필터

- [ ]  〔신규〕 검색창에 "교과목명, 교수명 검색" 안내 문구가 보인다.
- [ ]  과목명 일부만 입력해도 강의가 검색된다.
- [ ]  교수명으로 강의를 검색할 수 있다. *(서버가 교수명까지 검색하는지 실서버로 반드시 확인)*
- [ ]  검색 결과 카드에 과목명·교수명·학수번호·요일/시간·강의실·학점이 모두 표시된다.
- [ ]  결과가 없으면 "조회된 강의가 없습니다", "검색어나 필터 조건을 변경해 보세요"가 표시되고 화면이 멈추지 않는다.
- [ ]  ⚠️ 검색어 앞뒤에 공백을 넣어("  운영체제  ") 검색해도 공백 없이 검색한 것과 같은 결과가 나온다. *(시간표 검색창과 마법사 검색창의 공백 처리 방식이 서로 달라, 두 화면 모두에서 확인할 것)*
- [ ]  〔신규〕 공백만 입력하고 검색했을 때 화면이 깨지지 않는다.
- [ ]  전공/영역 필터(단과대 → 학과)를 적용하면 해당 학과 강의만 표시된다.
- [ ]  학년 필터를 1개 또는 여러 개 선택해 적용할 수 있다.
- [ ]  시간 필터에서 30분 단위 시간대를 여러 개 골라 적용할 수 있고, 요약 문구가 "월(09:00~10:30)" 형태로 표시된다.
- [ ]  이수구분 필터에서 "전공"을 고르면 전공기초·전공핵심·전공심화가 모두 포함되어 결과가 0건이 되지 않는다.
- [ ]  〔신규〕 이수영역 필터("(핵심)인문" 등)를 적용할 수 있다.
- [ ]  학점 필터(1~4학점)를 적용할 수 있다.
- [ ]  "수업 유형" 필터에서 이러닝/온라인 과목만 걸러낼 수 있다.
- [ ]  여러 필터를 동시에 적용하면 모든 조건을 만족하는 강의만 표시된다.
- [ ]  〔신규〕 적용한 필터 개수가 "필터 N" 배지에 정확히 표시된다.
- [ ]  요약 칩의 X 버튼으로 조건을 하나씩 해제할 수 있고, 나머지 조건은 유지된다.
- [ ]  〔수정〕 "초기화" → 확인 후 **"적용하기"까지 눌러야** 실제로 전체 필터가 풀린다. *(원본은 "초기화 시 모든 강의가 다시 표시된다"였으나, 초기화만으로는 확정되지 않는다)*
- [ ]  〔신규〕 시간 필터 화면의 "초기화"는 시간 조건만 지우고 다른 필터는 유지한다.
- [ ]  〔신규〕 필터를 바꾸다 저장하지 않고 뒤로 가면 "변경사항 적용 안 함" 확인이 뜨고, 적용 안 함을 고르면 기존 필터가 그대로 유지된다.
- [ ]  〔수정〕 필터를 적용한 뒤 앱을 완전히 종료했다 다시 실행해도 필터가 **유지된다**. *(원본은 "정해진 정책대로 유지 또는 초기화"였으나, 실제 정책은 유지로 확정되어 있다)*
- [ ]  〔신규〕 필터를 한 번도 적용한 적 없는 계정으로 처음 진입하면 본인 학과가 기본 전공 필터로 잡힌다. 이후 직접 해제하면 그 상태가 유지된다.
- [ ]  ⚠️ 정렬 옵션에 "학년순"이 있고, 전공 강의가 학년순으로 정렬된다. *(현재 정렬은 기본순/별점높은순/담은인원많은순 3종만 있다)*
- [ ]  〔신규〕 ⚠️ "별점높은순" 정렬이 실제로 동작한다. *(일부 과목에만 평점 값이 들어 있어 나머지는 정렬 효과가 없다)*
- [ ]  〔신규〕 검색 결과를 스크롤해 다음 페이지를 불러오는 중 필터를 바꾸면 이전 결과가 즉시 사라지고 새로 로딩된다.
- [ ]  〔신규〕 앱에서 필터 화면을 별도 화면으로 열었다가 돌아왔을 때 적용한 필터가 편집 화면에 반영된다. *(실기기에서 확인 — 화면 전환 타이밍에 따라 누락될 수 있는 지점)*

## 3. 강의 추가·수정·삭제

추가 경로가 두 가지다. 검색 결과에서 개설강의를 담는 경로와, "일정 추가" 화면에서 직접 만드는 경로를 각각 확인한다.

- [ ]  검색 결과에서 강의 카드를 펼치면 "시간표에 추가" 버튼이 보이고, 누르면 시간표에 담긴다.
- [ ]  이미 담은 분반은 버튼이 "추가됨"으로 바뀌고 눌리지 않는다.
- [ ]  ⚠️ 이미 담은 강의와 시간이 겹치는 분반을 추가하면, 충돌한 강의의 과목명·교수명·분반·요일·시간이 표시된다. *(원본의 충돌 관련 두 항목을 하나로 합쳤다. 현재 겹침 여부를 앱에서 미리 검사하지 않으므로, 겹치는 강의가 그대로 추가되는지·서버가 막는지·막힌다면 어떤 문구가 뜨는지 반드시 실제로 확인해 기록)*
- [ ]  추가에 성공하면 시간표와 전공/교양/기타/총학점 배지가 즉시 갱신된다.
- [ ]  "일정 추가" 화면에서 이름을 비우고 저장하면 "이름을 입력해 주세요."가 표시되고 입력란으로 포커스가 이동한다.
- [ ]  종료 시간이 시작 시간보다 빠르거나 같으면 "일정 N의 종료 시간이 시작 시간보다 빠르거나 같아요."가 뜨고 저장되지 않는다.
- [ ]  ⚠️ 시작·종료 시간을 10분·15분 단위로만 입력할 수 있다. *(현재 1분 단위로 자유 입력되며 그대로 저장된다)*
- [ ]  〔신규〕 시간 슬롯을 여러 개 추가할 수 있고, 슬롯이 하나만 남으면 삭제 버튼이 사라진다.
- [ ]  〔신규〕 같은 일정 안에서 시간 슬롯끼리 겹치게 입력해도 저장되는지 확인한다. *(슬롯 간 충돌 검사가 없어 그대로 저장될 것으로 예상)*
- [ ]  기존 일정을 수정하면 새 일정이 생기지 않고 해당 일정만 바뀐다.
- [ ]  강의/일정 삭제 시 `"{이름}" 강의를 시간표에서 삭제하시겠습니까?` 확인이 표시된다.
- [ ]  삭제를 취소하면 항목이 그대로 유지된다.
- [ ]  삭제 완료 후 시간표와 총학점이 즉시 갱신된다.
- [ ]  ⚠️ 서버 오류로 삭제가 실패하면 항목이 그대로 남고 재시도 안내가 표시된다. *(현재는 실패 안내만 뜨고 재시도 유도 문구·버튼이 없다)*
- [ ]  〔신규〕 "강의계획서" 버튼은 현재 항상 준비 중 안내만 뜬다. 동작하는 기능으로 오인해 결함으로 올리지 않는다.

## 9. 친구 요청·알림함

- [ ]  친구 요청 알림을 누르면 채팅 목록의 "친구" 탭으로 이동한다.
- [ ]  친구 요청을 수락하면 친구 목록에 즉시 반영된다.
- [ ]  ⚠️ 친구 요청 거절 안내에 상대방 닉네임이 표시된다. *("친구" 탭에서는 확인창 없이 바로 거절되고, 프로필 모달에서는 "친구 요청을 거절할까요?"만 뜬다. 두 경로 모두 확인)*
- [ ]  ⚠️ 이미 처리된 친구 요청을 다시 처리하려 하면 실패 안내가 뜬다. **재현 방법**: 브라우저 탭 두 개에서 같은 계정으로 로그인하고, 한쪽에서 수락한 뒤 다른 쪽(목록이 갱신되기 전)에서 같은 요청을 다시 수락·거절해 본다. *(현재 실패해도 아무 반응이 없을 것으로 예상)*
- [ ]  〔신규〕 ⚠️ 수락·거절 버튼을 빠르게 여러 번 눌러도 요청이 한 번만 처리된다.
- [ ]  읽지 않은 알림이 있으면 헤더에 배지가 표시된다.
- [ ]  알림을 열면 읽음 상태로 바뀐다.
- [ ]  모든 알림을 읽으면 배지가 사라진다.
- [ ]  알림 종류별로 올바른 화면으로 이동한다(학과공지 / 학교공지 / 채팅 / 친구 / 시간표 브리핑 / 학사일정).
- [ ]  삭제되었거나 이미 나간 채팅방의 알림을 눌러도 앱이 종료되지 않고 채팅 목록으로 안전하게 돌아온다.
- [ ]  동일한 알림이 목록에 중복으로 표시되지 않는다.
- [ ]  〔신규〕 (앱) 푸시 알림을 눌러 앱에 진입했을 때도 그 알림이 읽음 처리되고 배지가 갱신된다. *(웹에서 목록을 눌러 읽는 경로와 처리 방식이 달라 각각 확인 필요)*
- [ ]  〔신규〕 "보낸 친구 요청" 목록에서 요청을 취소할 수 있고, 실패 시 안내가 뜬다.
- [ ]  〔신규〕 헤더의 알림 배지와 홈 화면의 "새 공지" 점은 서로 다른 기능이다. 하나가 잘못 동작해도 같은 항목으로 묶어 기록하지 않는다.

## 10. 강의 시작 전 알림

〔수정〕 **섹션 제목부터 바뀌었다.** 원본 "강의 1시간 전 알림"이 아니라 "수업 시작 전 N분 알림"이며, 기본값은 10분이다. 발송 자체는 앱에서만 확인할 수 있다. 원본의 "구현 완료 후 QA" 단서 중 설정 화면은 이미 구현되어 있어 웹에서 지금 테스트 가능하다.

- [ ]  〔신규〕 신규 계정으로 알림 설정 화면에 들어가면 "10분 전"이 선택되어 있다.
- [ ]  〔신규〕 프리셋(5/10/15/20/30/45/60분 전)과 "직접 설정"을 고를 수 있다.
- [ ]  〔신규〕 "직접 설정"에 0 또는 181을 입력하면 "알림 시간은 1분에서 180분 사이로 입력해 주세요."가 뜨고 저장되지 않는다.
- [ ]  〔신규〕 프리셋에 없는 값(예: 37분)을 저장하면 "37분 전 (직접 설정)" 형태로 표시된다.
- [ ]  〔신규〕 "시간표 알림 받기"를 끄면 하위 옵션이 함께 숨겨진다.
- [ ]  〔신규〕 ⚠️ 네트워크를 차단한 상태로 알림 시간을 바꾸면 저장 실패가 사용자에게 안내된다. *(현재는 서버 저장에 실패해도 화면에는 항상 "저장됨"으로 표시된다)*
- [ ]  〔신규〕 설정을 바꾼 뒤 로그아웃하고 다른 기기에서 로그인했을 때 같은 설정이 보인다.
- [ ]  〔신규〕 ⚠️ 로그아웃 후 다른 계정으로 로그인했을 때, 이전 계정의 알림 설정이 잠깐이라도 보이지 않는다.
- [ ]  ⚠️ OS 알림 권한을 끈 상태로 설정 화면에 들어가면 권한 안내와 설정 이동 버튼이 표시된다. *(현재 미구현)*
- [ ]  〔수정〕 (앱) **설정한 시간에 맞춰** 알림이 발송된다. *(원본은 "1시간 전 발송"이었다)*
- [ ]  (앱) 알림에 과목명·시작 시간·강의실이 정확하게 표시된다.
- [ ]  (앱) 온라인 강의는 강의실 대신 온라인 수업임이 표시된다.
- [ ]  (앱) 알림을 누르면 시간표 화면으로 이동한다.
- [ ]  (앱) 삭제한 강의는 알림이 오지 않는다.
- [ ]  (앱) 시간을 변경한 강의는 변경된 시간 기준으로 알림이 온다.
- [ ]  (앱) 같은 강의 알림이 중복 발송되지 않는다.
- [ ]  (앱) 대표가 아닌 시간표의 강의는 알림이 오지 않는다.
- [ ]  〔신규〕 "당일 강의 목록 브리핑"이 설정한 시각에 하루 한 번 발송된다.

## 11. 오늘 강의 위젯

**전 항목이 앱 전용이다.** 웹에는 위젯 관련 구현이 없으므로, 웹 담당자는 이 섹션을 진행할 수 없다. 앱 담당자와 함께 진행하고, 웹 쪽에서는 시간표 데이터 자체가 정확한지만 확인한다.

- [ ]  〔신규〕 (웹) 시간표 화면에 보이는 과목명·시작/종료 시간·강의실 값이 위젯에 표시되는 값과 일치한다. *(원본 "과목명·시간·강의실 정보가 앱과 동일하다"를 웹에서 확인 가능한 형태로 분리했다)*
- [ ]  (앱) 오늘 수업이 시작 시간순으로 표시된다.
- [ ]  (앱) 대표 시간표를 변경하면 위젯도 갱신된다.
- [ ]  (앱) 오늘 수업이 없으면 공강 안내가 표시된다.
- [ ]  (앱) 날짜가 바뀌면 다음 날 시간표로 자동 갱신된다.
- [ ]  (앱) 로그아웃하거나 계정이 만료되면 위젯에 개인정보가 남지 않는다.
- [ ]  (앱) 작은 위젯에서도 텍스트가 잘리지 않거나 적절히 축약된다.
- [ ]  (앱) 네트워크가 없어도 마지막 갱신 시점이나 오류 상태가 표시된다.
- [ ]  〔신규〕 (앱) 강의실이 없는 온라인 강의를 위젯이 어떻게 표시하는지 확인하고, 앱 화면 표기와 어긋나지 않는지 본다.

## 12. 학점 계산기

- [ ]  〔신규〕 로그인 상태로 진입하면 서버에 저장된 성적이 표시된다.
- [ ]  〔신규〕 비로그인 상태로 진입하면 이 브라우저에 저장해둔 성적만 표시된다.
- [ ]  〔신규〕 성적 데이터가 하나도 없는 신규 계정으로 들어가면 현재 시점 기준 학기가 하나 자동 생성된다.
- [ ]  학과·학번 정보가 있는 계정으로 처음 들어가면 졸업요건 학과와 입학연도가 자동으로 채워진다.
- [ ]  〔신규〕 학과를 "선택 안 함"으로 직접 지우고 새로고침해도 다시 자동으로 채워지지 않는다.
- [ ]  졸업요건 데이터가 없는 학과를 고르면 "아직 {학과명}의 졸업요건 데이터가 없어요. 취득 학점은 직접 설정해 주세요."가 표시되고, 잘못된 계산 결과가 나오지 않는다.
- [ ]  〔신규〕 수집 구간을 벗어난 학번을 넣으면 가장 가까운 기준으로 대체되며 경고가 표시된다.
- [ ]  〔수정〕 총학점·전공·전공기초/전공핵심·교양이 구분되어 이수/필요/잔여 학점으로 표시된다. *(원본은 "전공·교양·일반선택·총학점" 4구분이었으나, 화면에 "일반선택" 구분은 없고 전공기초/전공핵심이 별도로 있다)*
- [ ]  〔신규〕 직접 입력한 과목만 있으면 전공기초·전공핵심은 자동 판정하지 않고 그 사유가 안내된다.
- [ ]  〔신규〕 핵심교양 영역 수 조건이 있는 학번대에서, 이수영역 정보가 없으면 그 사유가 안내된다.
- [ ]  〔신규〕 교양 학점이 상한을 넘으면 초과분 안내가 표시된다.
- [ ]  〔신규〕 정보기술대학 학과를 고르면 SW 필수교양이 면제 처리되어 목록에서 빠진다.
- [ ]  과목을 추가하고 과목별 학점과 예상 등급을 입력할 수 있다.
- [ ]  P 과목은 평점에서 제외되고 취득학점에는 포함된다. NP 과목은 둘 다에서 빠진다.
- [ ]  재수강으로 취소된 과목은 평점과 취득학점 모두에서 빠지고, 목록에는 흐리게 남는다.
- [ ]  값을 수정하면 결과가 즉시 다시 계산된다.
- [ ]  목표 취득학점 입력란에 문자를 넣으면 무시되고, 0 이하는 저장되지 않는다.
- [ ]  〔신규〕 목표 평점에 0 이하나 4.5 초과를 넣으면 "0보다 크고 4.5 이하인 값을 입력해 주세요."가 뜬다.
- [ ]  〔신규〕 목표 평점 달성에 필요한 평균 평점이 표시되고, 4.5를 넘는 불가능한 값일 때 적절한 안내가 나온다.
- [ ]  〔신규〕 남은 학점이 0일 때 필요 평점 안내가 깨지지 않는다.
- [ ]  〔신규〕 과목명이 빈 과목이 있으면 해당 학기로 이동하며 안내가 뜨고 저장이 중단된다.
- [ ]  〔신규〕 저장에 실패하면 "성적 저장에 실패했어요. 잠시 후 다시 시도해주세요."가 뜨고 화면이 죽지 않는다.
- [ ]  〔신규〕 저장하지 않고 다른 화면으로 이동하려 하면 확인 모달이 뜬다.
- [ ]  〔신규〕 시간표에서 과목을 불러올 때 학점 정보가 없는 일정도 최소 1학점 이상으로 들어간다.
- [ ]  〔신규〕 ⚠️ 5학점 이상 과목(캡스톤 등)을 성적 붙여넣기로 불러온 뒤 학점 드롭다운을 열면 그 값이 목록에 있다. *(현재 드롭다운은 1~4학점만 제공해, 열었다 닫는 것만으로 값이 바뀔 수 있다)*
- [ ]  〔신규〕 ⚠️ 브라우저 콘솔을 열어둔 채로 성적을 입력했을 때, 과목 정보가 콘솔에 출력되지 않는다. *(디버그 출력이 남아 있다)*
- [ ]  〔신규〕 비로그인 상태로 입력한 뒤 로그인만 하고 저장하지 않았을 때, 다른 기기에서는 그 데이터가 보이지 않는다는 점을 사용자가 알 수 있는지 확인한다.
- [ ]  〔신규〕 비로그인 상태로 입력한 뒤 브라우저 사이트 데이터를 지우면 입력 내용이 사라진다. 사전 경고가 있는지 확인한다.
- [ ]  〔신규〕 같은 학기에 동일한 과목명을 두 번 추가해도 경고 없이 저장되는지 확인한다.
- [ ]  ⚠️ 복수전공·부전공·편입 조건을 설정할 수 있다. *(현재 단일 학과·단일 입학연도만 지원한다)*

## 13. 강의 정원·수강 인원

**전 항목 신규.** 원본 배분표에만 있고 체크리스트가 없던 영역이라, 코드를 근거로 새로 작성했다.

- [ ]  〔신규〕 강의 검색 결과에 "정원 N명 · 수강 M명" 배지가 표시된다.
- [ ]  〔신규〕 정원과 수강인원 중 한쪽 값만 있는 강의는 있는 값만 표시된다.
- [ ]  〔신규〕 둘 다 없는 강의는 배지가 아예 표시되지 않는다.
- [ ]  〔신규〕 ⚠️ 그룹 시간표 마법사의 검색 결과도 시간표 검색과 같은 형식으로 표시된다. *(현재 "수강인원 / 정원" 순서로 표기가 반대다)*
- [ ]  〔신규〕 "담은인원많은순" 정렬의 기준이 실제 수강 인원이 아니라 찜한 인원임을 확인하고, 정원 마감으로 오인되지 않는지 본다.
- [ ]  〔신규〕 ⚠️ 정원이 다 찬 강의에 마감 표시가 있다. *(현재 마감 여부를 판정하는 로직이 없어 사용자가 두 숫자를 직접 비교해야 한다)*
- [ ]  〔신규〕 수강인원이 정원보다 많은 강의를 화면이 어떻게 표시하는지 확인한다.
- [ ]  〔신규〕 정원이 0명인 강의(폐강)를 화면이 어떻게 표시하는지 확인한다.
- [ ]  〔신규〕 검색 화면을 열어둔 채 시간이 지나도 정원·수강인원이 갱신되지 않는다는 점을 확인하고, 수강신청 기간에 문제가 될지 판단한다.

## 14. 성적 가져오기

〔수정〕 **섹션 전체의 전제가 바뀌었다.** 이미지 인식이 아니라 텍스트 붙여넣기다. 스마트캠퍼스 성적표 화면을 드래그 복사해서 붙여넣는 방식이므로, 원본의 이미지 관련 항목(흐린 이미지, 표 인식 정확도 등)은 이 기능에 적용되지 않는다.

- [ ]  〔수정〕 스마트캠퍼스 "과목별 성적" 표를 **복사해 붙여넣으면** 과목명과 과목코드가 추출된다.
- [ ]  〔수정〕 학점·등급·이수구분이 각각 올바른 열로 인식된다.
- [ ]  〔수정〕 화면 전체를 "모두 선택"해 복사해도 상단 메뉴나 학기 요약표가 과목으로 잘못 들어가지 않는다. *(원본 "표의 행과 열이 다른 과목과 섞이지 않는다"를 붙여넣기 방식에 맞게 재작성)*
- [ ]  〔신규〕 (iOS 등) 표 중간부터 드래그해 복사해도 온전한 행은 정상 인식된다.
- [ ]  P / NP 과목이 등급으로 정상 인식된다.
- [ ]  "재수강성적취소" 표시가 있는 행이 흐리게 표시되고 "성적취소" 배지와 함께 평점에서 빠진다는 안내가 나온다.

## 15. 이미지로 시간표 가져오기

- [ ]  〔신규〕 인천대 수강신청 장바구니 캡처를 넣으면 수강번호로 정확한 분반이 자동 선택된다.

- [ ]  같은 과목의 여러 분반이 후보 목록에서 교수명·수강번호·시간으로 구분된다.

- [ ]  ⚠️ 기존 시간표와 합칠지 덮어쓸지 선택할 수 있다. *(현재 선택지 없이 항상 추가만 되며, 겹치는 항목은 안내 없이 빠진다)*
- [ ]  ⚠️ 중복이거나 시간이 겹치는 강의를 **저장하기 전에** 알려준다. *(현재는 저장을 시도한 뒤 "이미 등록되었거나 시간이 겹치는 N개는 제외했습니다."로 사후 안내된다)*
- [ ]  취소하고 나가면 시간표가 변경되지 않는다.
- [ ]  ⚠️ 매우 큰 이미지(10MB 이상)나 이미지가 아닌 파일을 선택하면 안내가 표시된다. *(현재 용량·형식 검증이 전혀 없다. 저사양 기기에서 화면이 멈추는지 함께 확인)*
- [ ]  〔신규〕 4000px 이상 고해상도 이미지를 넣었을 때 분석이 완료되고 화면이 멈추지 않는다.
- [ ]  〔신규〕 분석 중 뒤로 가면 처음 화면으로 돌아오고, 다시 분석해도 정상 동작한다.
- [ ]  〔신규〕 ⚠️ 여러 강의를 저장하다 중간에 실패하면, 어떤 강의가 실패했는지 알 수 있다. *(현재 개수만 안내되고 목록은 나오지 않는다)*
- [ ]  〔신규〕 ⚠️ 저장에 실패했을 때 서버 원문 대신 이해할 수 있는 안내가 표시된다. *(이 화면은 서버 메시지를 그대로 노출한다)*
- [ ]  〔신규〕 분석 중 앱을 백그라운드로 보냈다가 돌아와도 정상 동작한다.

## 16. 공통 동작·보안

- [ ]  네트워크가 느릴 때 로딩 상태가 표시된다.
- [ ]  네트워크가 끊겼을 때 재시도 안내가 표시된다.
- [ ]  로그인이 만료되면 "로그인 정보가 만료되었습니다. 다시 로그인해 주세요." 안내 후 안전하게 로그인 화면으로 이동한다.
- [ ]  〔신규〕 화면이 여러 요청을 동시에 보내는 상황에서 토큰이 만료되어도 재로그인 화면이 여러 번 뜨거나 안내가 중복되지 않는다.

- [ ]  〔신규〕 미저장 변경사항이 있는 화면에서 헤더 뒤로가기, 화면 전환, (안드로이드) 하드웨어 백버튼 **세 경로 모두** 확인 모달이 뜬다.
- [ ]  〔신규〕 (안드로이드) 모달이나 바텀시트가 열린 상태에서 백버튼을 누르면 화면이 아니라 그 오버레이만 닫힌다.

- [ ]  ⚠️ 서버 오류가 나도 원문 대신 사용자가 이해할 수 있는 안내가 표시된다. **화면마다 다르므로 화면별로 확인**한다. 글쓰기는 상태별 안내가 잘 되어 있고, 이미지로 시간표 가져오기는 서버 원문을 그대로 노출한다.

- [ ]  로그아웃 후 이전 사용자의 데이터가 화면에 남지 않는다.
- [ ]  〔신규〕 ⚠️ 로그아웃하고 **곧바로 다른 계정으로 로그인**했을 때(새로고침 없이) 이전 계정의 시간표·성적·메모가 잠깐이라도 보이지 않는다. *(캐시가 정리되지 않아 남을 수 있는 지점. 실기기에서 재현할 것)*
- [ ]  〔신규〕 ⚠️ 같은 기기에서 로그아웃 후 다른 계정으로 로그인했을 때 이전 계정으로 푸시 알림이 오지 않는다. *(수동 로그아웃과 토큰 만료 로그아웃의 정리 항목이 서로 달라, 두 경로를 각각 확인)*
- [ ]  〔신규〕 로그아웃 상태에서 로그인이 필요한 화면에 접근하면 안전하게 막힌다.
- [ ]  〔신규〕 앱에서 로그인 화면이 별도 화면으로 열린 경우, 로그인 후 원래 화면에도 로그인 상태가 반영된다.

## 서버 확인이 필요한 항목 〔신규 섹션〕

웹 화면만으로는 통과/실패를 판정할 수 없어, 서버 담당자와 함께 확인해야 하는 항목이다. 웹 담당자가 붙잡고 있으면 시간만 쓴다.

- [ ]  대표 시간표를 삭제했을 때 서버가 다른 시간표를 대표로 다시 지정하는가.
- [ ]  강의 검색의 검색어가 교수명까지 검색하는가. 앞뒤 공백을 서버가 걷어내는가.
- [ ]  친구 시간표·채팅방 시간표 조회 응답에 상대방의 개인 메모가 포함되는가.
- [ ]  친구 관계를 끊은 뒤 그 사람의 시간표를 요청하면 서버가 거부하는가.
- [ ]  이미 처리된 친구 요청을 다시 처리하면 서버가 어떤 응답을 주는가.
- [ ]  오픈채팅방 ID로 공강 조회를 직접 요청하면 서버가 막는가. *(앱은 메뉴만 숨길 뿐 요청 자체를 막지 않는다)*
- [ ]  다른 사용자의 시간표·메모·성적 ID로 직접 요청하면 서버가 막는가.
- [ ]  같은 알림이 중복 발송되지 않도록 서버에서 처리하는가.
- [ ]  강의를 시간이 겹치게 추가하려 할 때 서버가 막는가. 막는다면 어떤 메시지를 주는가.
- [ ]  알림 설정 저장 API가 실제로 배포되어 있는가.

## 진행 순서

원본 순서에 1번과 5번을 추가했다.

1. 〔신규〕 위 체크리스트에서 ⚠️ 표시된 항목을 **먼저** 테스트한다. 실패가 예상되는 지점이므로, 실제 동작을 기록해두면 수정 후 재검증 기준이 된다.
2. 나머지 정상 시나리오를 담당 영역별로 1차 테스트한다.
3. 실패 항목에 테스트 환경(Web/Android/iOS, 계정), 재현 순서, 실제 결과, 캡처를 기록한다.
4. 교차 검증 담당자가 실패 항목과 주요 정상 항목을 재검증한다.
5. 〔신규〕 "서버 확인이 필요한 항목"은 서버 담당자와 함께 별도로 확인한다.
6. 수정 배포 후 최초 발견자가 최종 재검증한다.
